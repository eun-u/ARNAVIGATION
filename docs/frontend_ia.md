# NaVi 모바일 프론트 IA

## 목적

NaVi 시민용 화면은 `Plan → Navigate → Explain` 순서로 사용자가 다음 세 가지를 빠르게 판단하도록 돕는다.

1. 지금 어디로 가야 하는가
2. 이 경로가 내 이동 조건에서 통과 가능한가
3. 왜 일반 경로와 다른가

화면의 정보 위계는 항상 `다음 행동 → 통과 상태 → 거리·시간 → 우회 차이 → 판단 근거 → 출처` 순서를 따른다.

## 시민 정보 구조

```text
NaVi
├─ 시작
│  └─ 브랜드 약속 / 데모 데이터 고지
├─ 경로 계획
│  ├─ 출발지
│  ├─ 목적지
│  └─ 이동 조건 프리셋
├─ 경로 결과
│  ├─ 접근 가능 추천 경로
│  ├─ 일반 경로 비교
│  ├─ 예상 거리·시간
│  ├─ 검증 상태
│  └─ 경로 추천 이유
├─ 이동 안내
│  ├─ 카메라 AR
│  ├─ 지도 보기
│  ├─ 음성 안내
│  └─ 상태 변화 재탐색
├─ 설명
│  ├─ 제외된 구간
│  ├─ 데이터 출처
│  └─ 검증·최신성
└─ 현장 제보
   ├─ 제보 유형
   ├─ 사진·메모
   └─ 검수 전 미반영 고지
```

관리자 검수는 시민 흐름과 분리된 `/review`에서 제공한다. 시민 제보나 AI 후보가 공용 그래프에 직접 반영되는 경로는 두지 않는다.

## 내비게이션 원칙

- 첫 방문은 시작 화면을 보여주고 같은 브라우저 탭에서는 다시 표시하지 않는다.
- 브라우저 뒤로가기는 직전 화면과 경로 상태를 복원한다.
- AR에서는 앱 전역 내비게이션을 숨기고 `지도`, `음성`, `제보`, `종료`만 제공한다.
- 경로 결과와 설명 화면은 동일한 route session을 공유한다.
- API가 실패하면 `데모 모드`를 명시하고 동일한 화면 흐름을 유지한다.
- 데모 제보는 기기에만 임시 저장하며 제출 또는 검증 완료로 표현하지 않는다.

## 콘텐츠 원칙

- 장애 유형보다 사용자가 원하는 이동 조건을 먼저 묻는다.
- `안전한 경로` 대신 `설정한 조건에서 접근 가능한 경로`라고 표현한다.
- synthetic, 추정, 미검증 데이터는 항상 화면에 고지한다.
- 색상만으로 상태를 구분하지 않고 아이콘과 상태명을 함께 표시한다.
- AI 후보, 사람 검수, 승인 데이터를 같은 신뢰 수준으로 표현하지 않는다.
