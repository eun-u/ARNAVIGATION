# Data Trust Model — 2축 분리

**통행 가능성**과 **근거 수준**은 다른 축이다. 둘을 하나로 합치면 "갈 수 있는 길 추천 앱"에 머문다.

## 축 A — 통행 상태 (라우팅이 결정)

| 값 | 표기 | 정의 |
|---|---|---|
| `accessible` | 통과 가능 (pass) | 모든 hard constraint를 만족 |
| `conditionally_accessible` | 조건부 (warning) | 시간대·날씨·엘리베이터 운행 등에 따라 달라짐 |
| `blocked` | 통행 제한 (danger) | hard constraint 위반이 확정 |
| `unknown` | 정보 없음 (unknown) | 판단에 필요한 속성이 없음 |

## 축 B — 근거 수준 (데이터 출처가 결정)

| 값 | 표기 | 출처 |
|---|---|---|
| `field_verified` | 현장 확인 | 사람이 현장에서 확인하고 검수 통과 |
| `institutional` | 공공데이터 | 안양시 횡단보도 현황 등 · 위치 추정 포함 |
| `map_data` | 지도 기반 | OSM 스냅샷 · 보도 전용 정밀망 아님 |
| `ai_inferred` | AI 후보 | 검수 대기 · **라우팅에 사용하지 않음** |
| `unknown` | 수집 안 됨 | — |

## 교차 표기 — 같은 "통과 가능"도 다르게 보인다

| 축 A | 축 B | 화면 표기 |
|---|---|---|
| accessible | field_verified | `통과 가능` + `턱 2cm 이하` / 캡션 `현장 확인 · 2026.09.15` |
| accessible | map_data | `통과 가능 · 확인 필요` + `턱 2cm 이하 추정` / 캡션 `지도 데이터 기반 · 현장 미확인` |
| unknown | unknown | `정보 없음` + `턱 높이 미수집` / 캡션 `기본적으로 경로에서 제외` |
| — | ai_inferred | `AI 후보` 배지 · 흐린 표시 / 캡션 `검수 대기 · 경로 계산에 쓰이지 않음` |

배지는 축 A만 표현한다. 축 B는 캡션(`metric.uncertainty`)으로 분리한다.

## 신선도 — 언제 다시 물어볼 것인가

| 근거 | 유효 기간 | 만료 후 |
|---|---|---|
| 현장 확인 | 180일 | 확인 필요로 강등 · 도착 화면에서 재확인 요청 |
| 공공데이터 | 갱신 주기 따름 | 출처 갱신일을 그대로 노출 |
| 지도 기반 | 스냅샷 시점 고정 | 스냅샷 일자를 항상 함께 표시 |
| 시민 제보 | 현재 세션 | 검수 통과 전까지 공용 Graph 미반영 |

## 경로 결과 요약 표기

구간 수를 그대로 보여준다. **"신뢰도 82%" 같은 단일 점수로 합치지 않는다.** 합치는 순간 근거가 사라진다.

```
현장 확인 6   추정 7   정보 없음 5
```

## 문구 규칙

- "안전한 경로" ✕
- "설정한 조건에서 통과 가능한 경로" ○
- 단정형 대신 근거를 붙인 서술형
- AI 후보와 사람 검수를 같은 무게로 쓰지 않는다

이 모델을 지키면 NaVi는 "갈 수 있는 길 추천 앱"이 아니라
**근거와 불확실성을 함께 보여주는 접근성 경로 시스템**이 된다.
