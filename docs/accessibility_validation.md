# 접근성 검증 계획

명세는 이미 있다(WCAG 2.2 AA, 48dp 터치 타깃, 엄지 영역, HIG, Material 3).
다음은 **실제 검증**이다. 이 문서는 검증 계획과 폴백 설계이며, 결과는 기기에서 직접 돌려야 나온다.

## 검증 항목

| 항목 | 합격 기준 | NaVi에서 특히 위험한 화면 |
|---|---|---|
| 시스템 글자 200% | 잘림·겹침 없음, 모든 CTA 도달 가능 | 경로 결과 시트 · 재탐색 비교 · U-1 선택지 목록 |

## 글자 200%에서의 동작

시트가 세로로 늘어나고 지도가 줄어든다. **가로 배치를 세로로 바꾸고, 잘라내지 않는다.**
와이어프레임: `docs/wireframes/final/f-A1-Accessibility.html`

## 고대비 · blur 0 폴백

유리·그림자·굴절이 전부 사라져도 **층·순서·행동이 그대로**여야 한다. 경계는 선으로 대체한다.
`frontend/tokens.css`의 `@media (prefers-contrast: more)` 와 `@supports not (backdrop-filter)` 가 자동 전환한다.
Android는 `NaviGlass.*Fallback` 값을 쓴다.

## TalkBack 읽기 순서 — 경로 결과

1. 목적지 이름
2. 통행 상태 배지
3. 소요 시간
4. 거리와 차이
5. 제외 구간 요약
6. 근거 보기
7. 안내 시작

지도 위 플로팅 컨트롤은 시트 **이후**에 읽는다. 장식 SVG는 전부 `aria-hidden` / `contentDescription = null`.

## 이미 알고 있는 위험

- 반투명 CTA는 흰 글자 기준 4.5:1 미만이 된다. 최종본은 Primary CTA를 `#2A5FE8 → #5A3FD6` 불투명 브랜드 글래스로 고정해 **5.4:1**을 확보했다.
- 남은 위험: 지도 위 **Focus Glass 배너**와 AR 상태 칩. 직사광선 테스트 결과에 따라 불투명 폴백을 기본값으로 올릴지 결정한다.
- `text.muted`(#737D8C)는 흰 바탕 4.6:1이다. **13sp 미만에 쓰면 기준 미달**이 된다.
